# Спека: SMTP-проверка через внешний раннер (Emails, этап 2)

- Дата: 2026-10-20. Ветка: `feature/email-verify` (форк `timujinne/phoenix_kit_emails`).
- Продолжает спеку этапа 1 `2026-10-19-email-verification.md` и заменяет в ней план SMTP-стадии (§3 «SMTP (этап 2)», §6 «Троттлинг»).
- Статус: **утверждена** (голова, 20.10; решения Q10–Q19 — раздел 11, Q13 — ответ владельца).

## 0. Слова владельца (Q2, 20.10, дословно)

> «Нужно было бы гнать локально от пользователя, который запускает, прямо с его компьютера. С Docker1 отправлять — плохая идея. Собственный VPS — сложно. Это должна быть настройка самого пользователя: он выбирает, откуда. Например для Hydroforce — NewServer. Мне нужно понимать, как дать ему права/возможность подключиться. Всё это в интерфейсе лаконично.»

Что из этого следует:
- SMTP-соединения открывает **машина пользователя**: агент («раннер») на его компьютере, например на Windows-машине NewServer у Hydroforce.
- Сайт PhoenixKit только **раздаёт задания** и **принимает результаты**.
- Откуда гнать SMTP, выбирает сам пользователь в настройках.
- Право подключиться — **токен**. Его выпускают в той же настройке, и он даёт доступ только к заданиям SMTP-проверки.

## 1. Режимы (настройка `email_verify_smtp_mode`)

| Режим | Кто открывает порт 25 | Когда подходит |
|---|---|---|
| `off` (по умолчанию) | никто | Как сейчас: прошедший MX адрес получает `not_sure` с пометкой «Домен OK (без SMTP)» |
| `runner` | раннер на машине пользователя | Основной режим. Hydroforce → NewServer |
| `local` | сам сервер сайта | Сервер с чистым IP, на котором нет чужих сайтов. В UI предупреждение, что идёт с IP сервера. Для Hydroforce не включать: docker1 |

Булев `email_verify_smtp_enabled` из этапа 1 заменяется режимом. Этап 1 ещё не выпущен, поэтому переходный фолбэк не нужен. В ветке ключ просто переименовывается вместе с тестами.

Обе рабочие ветки (`runner` и `local`) берут задания из **одной очереди** и сдают результат в **один классификатор** (п. 4). `local` — это встроенный раннер в виде Oban-воркера, другого пути у него нет.

## 2. Доступ раннера — через Machine API ядра, без второго механизма

Сверено со спекой I305 (`phoenix_kit-worktrees/i305-api-neutral/docs/superpowers/specs/2026-10-20-api-module-neutral.md`) и кодом ядра 2.63.0.

**Публичный клиентский токен из I305 не подходит.** Это анонимный токен публичной аудитории (`/api/public/v1`, бывший cart token): его нельзя отозвать, у него нет владельца и прав. Раннер же пишет результаты проверки в базу сайта, значит это привилегированный клиент.

**Подходит admin-аудитория ядра как есть.** В 2.63.0 уже есть:
- ключи `pk_<8hex>_<43b64url>` в `phoenix_kit_api_keys`: хранится SHA-256 секрета, токен показывается один раз;
- у ключа есть scopes, `allowed_ips`, `expires_at`, `revoke`/`rotate`;
- `last_used_at` (пишется не чаще раза в минуту);
- права владельца ключа проверяются заново на каждом запросе;
- лимиты: `api_admin_rate_per_min` = 600 единиц/мин на ключ;
- журнал `api.request`.

Модуль Emails объявляет **два тула** через `api_tools/0`:

| Тул | Что делает | Поля Tool |
|---|---|---|
| `emails.claim_smtp_jobs` | Сердцебиение раннера плюс выдача заданий в аренду. Ответ содержит настройки (MAIL FROM, HELO, таймауты) и сигнал паузы | `audience: :admin`, `scope: "emails.smtp_runner:run"`, `permission: "emails"`, `replay: false` |
| `emails.report_smtp_results` | Приём сырых итогов SMTP-сессий, не больше `max_report` адресов за вызов | то же, `annotations: %{idempotent: true}`, `replay: false` (дедупликация своя, по `id` и `lease`) |

Транспорт — обычный `POST /api/admin/v1/<tool>` с заголовком `Authorization: Bearer pk_…`. Новых маршрутов, таблиц ключей и схем авторизации нет. Admin-пути переименование I305 не затрагивает.

Ограничения ядра, которые учитываются в дизайне:
- **Правило подтверждения пакета.** Admin-запись, в которой больше `api_confirm_batch_over` строк (по умолчанию 50), требует подтверждения человеком. Раннер подтвердить не может. Поэтому `max_report = min(50, FlowConfig.confirm_batch_over())` сервер отдаёт в каждом ответе `claim`, а раннер его соблюдает. `claim` списков на вход не принимает.
- **Machine API (admin) по умолчанию выключен** (`api_admin_enabled = false`), и модуль можно выключить через `api_disabled_modules`. Раздел настроек это показывает (п. 6). Включать или нет — вопрос Q12.
- **Отзыв ключа доходит до раннера за время до 60 с**: строка ключа кэшируется на 60 с.
- **Нужно ядро ≥ 2.63.0.** На более старом ядре (`Code.ensure_loaded?(PhoenixKit.API.Keys)` = false) режим `runner` в UI недоступен, с подсказкой. Тесты Emails сейчас идут на ядре 2.62.2 (`mix.lock`): lock поднимается до 2.63.x, диапазон зависимости `>= 2.21.3 and < 3.0.0` это допускает.

Чей это ключ (решение Q11):
- **Ключ того админа, который его выпустил.** Scope — один `emails.smtp_runner:run`, имя ключа «SMTP runner (<дата>)».
- В UI рядом со статусом раннера видно, **чьим ключом он работает** (имя/e-mail владельца ключа). Если владелец ключа деактивирован или потерял право `emails`, показывается предупреждение «раннер остановится: владелец ключа <имя> деактивирован / без права emails — выпустите новый токен».
- Право выпускать ключ — `api`: у Owner оно есть, Admin получает его только явно.

## 3. Очередь заданий SMTP

### 3.1 Данные (миграция Emails V5: только CREATE и ADD COLUMN в своих таблицах этапа 1)

`phoenix_kit_email_verify_smtp_queue` — одна строка на адрес, ждущий SMTP:

| Поле | Смысл |
|---|---|
| `uuid` | — |
| `email` (citext) | адрес, по которому хранится результат |
| `checked_as` | адрес после среза `+tag` |
| `domain` | — |
| `state` | `queued`, `leased`, `done` или `cancelled` |
| `attempts` | — |
| `not_before` | раньше этого времени задание не выдаётся |

- `(state, not_before)` и `(domain, state)`.

`phoenix_kit_email_verify_runners` — один раннер на один ключ:

| Поле | Смысл |
|---|---|

| `api_key_uuid` | — |

| `helo_auto` | rDNS своего IP по мнению раннера |
| `port25` | `open`, `blocked` или `unknown` |
| `port25_checked_at` | — |
| `last_seen_at` | — |
| `jobs_done` | — |
| `last_error` | — |
| `paused_until`, `pause_reason` | — |
| timestamps | — |

Без изменений берутся поля `phoenix_kit_email_verify_domains` из этапа 1 (созданы в V4): `catch_all`/`catch_all_checked_at`, `grey_at`, `last_smtp_at`, `blocks`, `paused_until`.

У `batch_items.state` появляется значение `awaiting_smtp`.

### 3.2 Как адрес попадает в очередь

- `VerifyEmailWorker` после шага MX при режиме ≠ `off`:
  - записывает промежуточный результат `not_sure`, `level "mx"`, `reason "smtp_pending"` (в UI: «Ждёт SMTP»);
  - ставит строку в очередь;
  - переводит item в `awaiting_smtp`.
- Пакет считается `done`, только когда у всех его item SMTP завершён.
- При режиме `off` всё как в этапе 1.
- Хвост этапа 1 №3: кэш `not_sure`/`smtp_disabled` при режиме ≠ `off` больше не считается окончательным, адрес идёт в SMTP. MX при этом берётся из кэша.
- Синхронный `verify/2` SMTP не ждёт и в очередь не ставит. Иначе — по опции `smtp: :enqueue`.

### 3.3 Выдача (`claim`)

Транзакция с `FOR UPDATE SKIP LOCKED`. Задания группируются в **сессии по домену**: одна сессия = одно SMTP-соединение, один `MAIL FROM` и до `rcpt_per_session` адресов одного домена. Домен выдаётся, только если одновременно выполнены условия:
- у него нет живой аренды (одна сессия на домен на весь сайт, как `WaitUntilDomainThreadFree` в LetsExtract);
- `now - last_smtp_at ≥ email_verify_domain_interval_s`;
- домен не на паузе (`paused_until`);
- у адресов `not_before ≤ now`.

Аренда длится `lease_s`. Протухшая аренда возвращает адреса в `queued` с `attempts + 1`. После `max_attempts` адрес финализируется как `not_sure` / `smtp_unavailable`.

Вход `claim`:
```json
{"max_sessions": 4,
 "runner": {"version": "1.0.0", "os": "Windows 10.0.17763 / PowerShell 5.1", "name": "NEWSERVER",
            "port25": "open", "helo_auto": "165-118-126-194.sta.estpak.ee"}}
```

Ответ:
```json
{"sessions": [{"lease": "…", "domain": "example.ee", "mx": ["mx1.example.ee", "mx2.example.ee"],
               "probe": "x7k2q9w4m1@example.ee",
               "rcpt": [{"id": "uuid", "email": "info@example.ee"}]}],
 "seen_ip": "165.118.126.194",
 "settings": {"mail_from": "verify@hydroforce.ee", "helo": null,
              "connect_timeout_s": 20, "read_timeout_s": 30, "max_report": 50,
              "idle_poll_s": 30, "selftest_host": "mx.hydroforce.ee"},
 "paused": null, "min_version": "1.0.0"}
```

Пояснения к ответу:
- `probe` (адрес для проверки catch-all) генерирует сервер. Он есть, только если `catch_all` домена неизвестен или его TTL истёк. Для disposable и free доменов probe не делается, как в оригинале.
- Пустой `sessions` — нормальный ответ простоя, `claim` работает как сердцебиение.

### 3.4 Приём (`report`)

Раннер присылает **сырые факты** сессии, а не вердикт:
```json
{"results": [{"lease": "…", "mx_used": "mx1.example.ee", "outcome": "answered",
              "steps": [{"cmd": "banner", "code": 220, "text": "…"}, {"cmd": "ehlo", "code": 250, "text": "…"},
                        {"cmd": "mail", "code": 250, "text": "…"}, {"cmd": "rcpt_probe", "code": 550, "text": "5.1.1 …"}],
              "rcpt": [{"id": "uuid", "code": 250, "text": "2.1.5 OK"}], "ms": 840}]}
```

- `outcome`: `answered`, `connect_failed`, `timeout` или `reset`.
- Тексты ответов обрезаются до 512 символов.
- Отчёт с чужим `lease` или по уже закрытому заданию игнорируется. Это даёт идемпотентность: повтор после сетевого сбоя безопасен.
- Протухшая аренда, которую ещё никому не выдали заново, принимается.

## 4. Классификация — только на сервере

Сервер решает, что значит ответ. Это даёт три вещи:
- приватные фразы Kellerman (greylist, quota, block) **не уезжают на машину пользователя**: они лежат в Hydroforce (`priv/email_verification/wordlists`, Q1);
- раннер остаётся тонким;
- у режимов `runner` и `local` одна логика.

| Факт | Статус / reason | Побочный эффект |
|---|---|---|
| `rcpt_probe` 250 | — | `catch_all = true` у домена (TTL 7 сут) |
| RCPT 250/251, домен не catch-all | `valid` / `smtp_ok`, `level "smtp"` | — |
| RCPT 250, домен catch-all | `not_sure` / `catch_all`, `catch_all = true` | — |
| RCPT 5xx, фраза блока или IP в тексте, и не исключение user-unknown («5.1.1», «user unknown»…) | `not_sure` / `smtp_blocked` | счётчик блоков домена |
| RCPT 5xx, фраза quota | `temp` / `mailbox_full` | — |
| RCPT 5xx, остальное | `invalid` / `mailbox_unknown` | — |
| RCPT 4xx (greylist или иное) | повтор через `email_verify_grey_retry_min` (20) | после `max_grey_attempts` (3) — `temp` / `greylisted` |
| MAIL FROM 5xx | `not_sure` / `mail_from_rejected` | в UI: «MX отверг MAIL FROM — проверьте адрес отправителя» |
| `connect_failed` на всех MX | повтор с backoff 1 мин → 5 мин | потом `not_sure` / `smtp_connect_failed` |
| `timeout` / `reset` | то же | потом `not_sure` / `smtp_timeout` / `smtp_reset` |

Автопауза защищает репутацию IP пользователя:
- 2 блока за час на одном домене → `paused_until = now + 1 ч` для домена (из этапа 1);
- 5 сессий подряд с `connect_failed` или `smtp_blocked` на ≥ 3 разных доменах → **пауза раннера**. Это признак закрытого порта 25 или IP в блок-листе. `claim` отвечает `paused`, UI показывает причину и кнопку «Снять паузу».

## 5. Раннер

### 5.1 Что делает

1. **Старт — самотест** (тот же самотест запускается отдельно ключом `-SelfTest`, после него раннер выходит). Вывод — по строке на проверку, `[OK]`/`[FAIL]`/`[WARN]` и подсказка, что делать:
   1. Сайт доступен по HTTPS, токен принят (`claim` с `max_sessions: 0`). 401/403 → «токен отозван или неверен, выпустите новый в Settings → Emails».
   2. Внешний IP раннера (`seen_ip`, который вернул сервер) и его rDNS (`[System.Net.Dns]::GetHostEntry`). Нет rDNS → `[WARN]`: многие MX отвергают такие соединения.
   3. Порт 25: соединение с `selftest_host:25` (сервер отдаёт MX своего домена — не чужой), баннер `220`, `QUIT`. Нет соединения → `[FAIL] порт 25 закрыт (провайдер/файрвол)`. Итог уходит на сервер как `port25`.
   4. MAIL FROM задан в настройках сайта. Пусто → `[FAIL]`, SMTP-сессии не начинаются (см. п. 11, Q13).
   - Если порт закрыт или MAIL FROM пуст, раннер всё равно шлёт сердцебиения, но сессий не берёт (`max_sessions: 0`), а UI пишет причину.
2. **Цикл.**
   - `claim(max_sessions = свободные слоты)`.
   - Каждая сессия идёт в своём потоке: MX по порядку (не больше 2), баннер, `EHLO helo` (при 5xx — `HELO`), `MAIL FROM:<mail_from>`, `RCPT TO:<probe>` (если есть), затем `RCPT TO` каждого адреса, `QUIT`.
   - **`DATA` не отправляется никогда.**
   - Результаты копятся и уходят `report` пачками по `max_report`.
   - При пустой выдаче раннер спит `idle_poll_s`.
3. **Сбои связи с сайтом.**
   - Backoff 5 → 60 с.
   - 401/403 — остановка с сообщением «токен отозван или неверен».
   - Ответ `min_version` выше своей версии — остановка с текстом «обновите раннер, ссылка — в настройках сайта».
4. **Что пишется на диск.** Ничего, кроме своего лога. Адреса в логе замаскированы (`in***@example.ee`).

### 5.2 Чем писать — сравнение

| | PowerShell 5.1 (`.ps1`) | Python 3 | Elixir escript |
|---|---|---|---|
| Что ставить на Windows NewServer | ничего: 5.1 встроен в Windows 10 и Server 2016+ | Python 3.x, либо exe через PyInstaller (бывают ложные срабатывания антивирусов) | Erlang/OTP (~100+ МБ). Один exe через Burrito — сборка с zig, нами не проверена |
| Параллельные сессии | RunspacePool: громоздко, но встроено | asyncio | процессы BEAM, лучше всех |
| SMTP-диалог | `TcpClient` и `StreamReader` вручную (~150 строк) | `smtplib` или сокеты | `:gen_tcp`; **тот же модуль, что у режима `local`** |
| Linux/macOS | только с PowerShell 7 (`pwsh`) | да | да, при установленном OTP |
| Автозапуск | Планировщик заданий (`-Install`) | то же | то же |
| Хранение токена | DPAPI (`ConvertFrom-SecureString`), встроено | файл или keyring | файл |
| Барьер запуска | ExecutionPolicy: запуск через `-ExecutionPolicy Bypass -File` | — | — |
| Наше тестирование | в контейнере нет `pwsh` (нужно ставить, Q18); 5.1-специфику проверить только на Windows | `python3` есть | `erl` есть; общий код покрыт ExUnit |
| Замечание | — | Владелец просил «не Python-сервис», хотя раннер — не сервис | — |

**Рекомендация: PowerShell-скрипт, совместимый с 5.1 и 7.** Причины:
- у пользователя Windows, и ставить ничего не нужно — это прямо про «лаконично» и «дать возможность подключиться»;
- раннер тонкий, вся логика на сервере, поэтому вторая реализация диалога маленькая;
- риск расхождения двух диалогов (Elixir для `local` и PS для `runner`) закрывается **общими тест-векторами** `priv/smtp_runner/test_vectors.json` (сценарий фейкового SMTP-сервера → ожидаемый `report`). По ним гоняются и ExUnit (`Smtp.Direct`), и тест раннера под `pwsh`.

Протокол — обычный JSON по HTTPS. Раннер на Python или escript для Linux/macOS можно добавить позже без изменений на сервере.

### 5.3 Раздача скрипта

- Скрипт лежит в модуле: `priv/smtp_runner/pk-smtp-runner.ps1`.
- Отдаётся админским маршрутом модуля `GET {admin}/emails/verification/pk-smtp-runner.ps1`: за авторизацией админки, по образцу `ExportController`.
- Секретов в скрипте нет. Адрес сайта и токен передаются параметрами.
- Версия скрипта = версия модуля.

## 6. UI: раздел «Проверка адресов (SMTP)» в Settings → Emails

Новая секция через `email_settings_sections/0` на странице ядра `/admin/settings/email-sending`, право `emails`. Лаконично — одна карточка:

```
Проверка ящиков (SMTP)
 ○ Отключено — только домен (результат «Домен OK (без SMTP)»)
 ○ Этот сервер — с IP сайта 203.0.113.5  ⚠ не включайте, если на этом IP другие сайты
 ● Раннер на вашем компьютере
     ● На связи · отклик 12 с назад · NEWSERVER · порт 25 открыт · в очереди 120
     [Выпустить новый токен]  [Отозвать]
     Подключение:
       1. Скачайте pk-smtp-runner.ps1 на компьютер, откуда пойдёт проверка.
       2. PowerShell: powershell -ExecutionPolicy Bypass -File pk-smtp-runner.ps1 -Server https://hydroforce.ee -Token <токен>
       3. Автозапуск: добавьте -Install (задача Планировщика, токен хранится зашифрованным).
       4. Статус выше станет «На связи».
 Отправитель MAIL FROM [                    ] пусто = адрес отправителя сайта (<from_email>)   HELO [пусто = rDNS IP раннера]
 ▸ Дополнительно (адресов за сессию 10, пауза домена 10 с, повтор greylist 20 мин × 3)
```

**Выпуск токена.**
- Кнопка вызывает `PhoenixKit.API.Keys.create_key/3` со scope `emails.smtp_runner:run`.
- Токен показывается **один раз** в модалке, вместе с командой из шага 2, куда он уже подставлен, и кнопкой «Копировать».
- Новый выпуск отзывает предыдущий ключ раннера: один раннер на сайт, Q15.
- Если у админа нет права `api`, кнопка неактивна с текстом «нужно право API». Можно выпустить ключ с этим scope и вручную в Settings → API.

**Статусы раннера.**
- «На связи»: `last_seen_at` моложе 3 × `idle_poll_s`.
- «Не на связи · последний отклик 20.10 07:15».
- «Ещё не подключался».
- «⚠ Порт 25 у раннера закрыт».
- «⏸ Пауза: <причина> [Снять паузу]».
- Обновление живое: PubSub `email_verify:runner`, широковещание при `claim` не чаще раза в 5 с.

**Предусловия** — показываются строкой со ссылкой, если не выполнены:
- ядро без Machine API;
- `api_admin_enabled` выключен;
- `emails` в `api_disabled_modules`;
- тулы скрыты через `api_disabled_tools`.

Newsletters и будущий CRM добавляют только статус «Ждёт SMTP» и счётчик в прогрессе пакета. Если раннер не на связи, в прогрессе пишется «SMTP ждёт раннер».

## 7. Безопасность

- **Токен даёт ровно два тула.** Он не открывает ни админку, ни другие API модуля. Отзыв срабатывает за ≤ 60 с. По желанию — `allowed_ips` (статический IP NewServer) и `expires_at`.
- **Раннеру уходят только адреса проверяемых списков и их MX** — это персональные данные. Раннер работает только с `https://` (исключение — `localhost` для разработки), без TLS не стартует. Раннер ничего не хранит, кроме маскированного лога.
- **Писем не отправляется**: только `RCPT`, затем `QUIT`. Репутацию IP пользователя бережёт автопауза (п. 4).
- **Журнал.** Сервер пишет в журнал `api.request` (ядро). Адреса в логах приложения маскируются — это же закрывает хвост этапа 1 №1.

## 8. Проверка

- **ExUnit, без сети:**
  - выдача и группировка, эксклюзивность домена, протухание аренды;
  - отчёты: валидация, идемпотентность, чужой `lease`;
  - вся таблица классификатора на фразах-фикстурах, не на приватных списках;
  - автопауза;
  - тулы через `PhoenixKit.API.Executor` с настоящим ключом в тестовой БД;
  - LiveView секции: выпуск и отзыв, статусы.
- **Тест-векторы:**
  - фейковый SMTP на `localhost` (ExUnit `:gen_tcp`);
  - тот же набор сценариев для раннера под `pwsh` 7 (если его разрешат поставить, Q18): фейковый SMTP-сервер плюс тестовый сервер сайта.
- **Живой SMTP** — по брифу, только 2–3 адреса своих доменов (hydroforce.ee, eurobalt.net):
  1. раннер под `pwsh` в контейнере против decor dev. IP при этом docker1, но адресов всего 2–3 и они свои;
  2. **на NewServer раннер запускает владелец или пользователь**: у меня доступа к этой машине нет. Проверить «На связи», `port25` и 2–3 адреса.
- Массовый SMTP в тестах — никогда.
