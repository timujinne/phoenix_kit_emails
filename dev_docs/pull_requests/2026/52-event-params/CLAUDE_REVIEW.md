## Summary
Hardens LiveView `handle_event/3` clauses across Blocklist, Details, Emails,
Queue, Metrics, Templates, TemplateEditor and two settings sections against
payloads of the wrong shape (integers, `nil`, maps, lists). Adds
`Utils.string_param/2`, `is_binary` guards with ignore-clauses, `URI.encode_query`
for navigation links, and fixes `determine_period/1` (`and` on a `Date` raised
`BadBooleanError` on every custom range). `change_period` no longer calls
`String.to_atom/1` on client input.

## Issues Found

### 1. [NITPICK] `change_period` relied on the period atoms already existing — FIXED
**File:** `lib/phoenix_kit/modules/emails/web/metrics.ex`
The whitelist guard (`period in @periods`) followed by `String.to_existing_atom/1`
only works if `:last_24_hours` & co. are in the atom table. They are defined in
`Emails`, which the LiveView's `mount` has already called, so it holds in
practice — but it is an implicit load-order dependency. Replaced with an explicit
`%{"last_7_days" => :last_7_days, ...}` map and `is_map_key/2` guard; no atom
conversion at all.
**Confidence:** 70/100

### 2. [OBSERVATION] Top-level non-map translation fields were untested
**File:** `test/.../web/event_payload_test.exs`
The tests cover non-string values *inside* a translation map, not
`"subject" => "plain"` / `42` / `["x"]` at the top level. Probed: the changeset
rejects them and the form still renders, so no code change was needed. Added a
validate/save × field × shape test matrix to pin it.

### 3. [OBSERVATION] Navigation paths interpolate an unencoded uuid
**File:** `web/emails.ex`, `web/queue.ex`, `web/templates.ex`
`"view_details"` / `"edit_template"` put a binary straight into
`Routes.path("/admin/emails/email/#{uuid}")`. A crafted string like `"../x"`
only navigates the sender to another same-origin admin path, so there is no
crash and no privilege gain. Left alone.

### 4. [OBSERVATION] `save` drops non-string `variables` silently
`variables` values are filtered by `drop_unrenderable_values/1` on save while
translations are refused. Dropped descriptions are regenerated by
`smart_description_for_variable/1`, so nothing is lost; the asymmetry is
deliberate and fine.

## What Was Done Well
The test file renders each page from the post-event assigns, so a handler that
survives but stores a raw value (moving the crash into the template) is caught.
`non_string_translation?` correctly refuses on save rather than silently saving
a version with no English.

## Verdict
Approved with fixes — one nitpick hardened, extra regression tests added.
